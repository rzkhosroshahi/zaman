# 🏗️ Architecture Guide

Understanding Zaman's internal architecture, design patterns, and how everything fits together.

## 📐 High-Level Overview

Zaman is built with a modular, layered architecture that separates concerns and promotes maintainability.

```
┌─────────────────────────────────────────┐
│         Component Layer                 │
│  (DatePicker, Calendar, TimePicker)     │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│         UI Components Layer             │
│  (Buttons, Items, Modals, Headers)      │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│         Business Logic Layer            │
│  (Hooks, Engines, State Management)     │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│         Core Layer                      │
│  (Date Engine, Calendar Engine)         │
└─────────────┬───────────────────────────┘
              │
┌─────────────▼───────────────────────────┐
│         Foundation Layer                │
│  (Utils, Theme, i18n, Types)           │
└─────────────────────────────────────────┘
```

---

## 🎯 Core Principles

### 1. **Separation of Concerns**

Each layer has a specific responsibility and doesn't leak implementation details:

- **Components**: User interface and interaction
- **Business Logic**: State management and user actions
- **Core**: Calendar calculations and date manipulation
- **Foundation**: Utilities, theming, and internationalization

### 2. **Composition over Inheritance**

Components are composed from smaller, reusable pieces:

```tsx
// DatePicker is composed of smaller components
<DatePicker>
  <Input />
  <FloatingElement>
    <CalendarWrapper>
      <Header />
      <RenderCalendar>
        <CalendarItem />
      </RenderCalendar>
    </CalendarWrapper>
  </FloatingElement>
</DatePicker>
```

### 3. **Controlled & Uncontrolled Modes**

All components support both patterns:

```tsx
// Uncontrolled (internal state)
<DatePicker defaultValue={new Date()} />

// Controlled (external state)
<DatePicker show={isOpen} onChange={handleChange} />
```

### 4. **Type Safety**

Full TypeScript coverage ensures type safety throughout the codebase.

### Core Layer

**Location**: `src/core/`

**Purpose**: Calendar and date calculation engines

```
core/
├── calendar-engine/         # Calendar calculations
│   ├── calendar-engine.ts   # Main engine
│   └── calendar-engine.types.ts
├── date-engine/            # Date manipulation
│   ├── date-engine.ts
│   └── date-engine.types.ts
└── range-engine/           # Range selection logic
    ├── range-engine.ts
    └── range-engine.types.ts
```

#### Calendar Engine

Handles calendar-specific logic:

- Month/year navigation
- Day calculations
- Week numbering
- Jalali ↔ Gregorian conversion

```tsx
// Example usage
import { CalendarEngine } from '@/core/calendar-engine'

const engine = new CalendarEngine({
  locale: 'fa',
  calendar: 'jalali'
})

const days = engine.getMonthDays(1402, 10) // Persian year/month
```

#### Date Engine

Provides date manipulation:

- Date parsing and formatting
- Date arithmetic
- Comparison operations
- Timezone handling

```tsx
import { DateEngine } from '@/core/date-engine'

const engine = new DateEngine()
engine.addDays(date, 7)
engine.isSameDay(date1, date2)
```

#### Range Engine

Manages date range selection:

- Range validation
- In-range checking
- Range calculations

```tsx
import { RangeEngine } from '@/core/range-engine'

const engine = new RangeEngine()
const isInRange = engine.isDateInRange(date, from, to)
```

#### Component Patterns

**Button Component**

```tsx
// src/components/core/button/button.tsx
interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'ghost'
  size?: 'sm' | 'md' | 'lg'
  onClick?: () => void
  children: React.ReactNode
}

export function Button({ variant, size, onClick, children }: ButtonProps) {
  const classes = cn('button', `button--${variant}`, `button--${size}`)

  return (
    <button className={classes} onClick={onClick}>
      {children}
    </button>
  )
}
```

```tsx
}

  // Rendering logic
}
```

## 🔄 Data Flow

### DatePicker Data Flow

```

    │
    ▼

    │
    ▼

    │
    ├─► Calendar Engine (date calculations)
    │
    ├─► Date Engine (formatting)

    ▼

    ▼
```

## 🎨 Styling Architecture

### CSS Variables Strategy

All styling uses CSS custom properties:

```css
/* Theme values become CSS variables */
:root {
  --zaman-primary: #3b82f6;
  --zaman-primary-light: #60a5fa;
  --zaman-radius-item: 8px;
  /* ... more variables */
}

/* Components use variables */
.calendar-item {
  background-color: var(--zaman-primary);
  border-radius: var(--zaman-radius-item);
}
```

### Benefits:

1. **Runtime theming**: Change themes without recompilation
2. **No CSS-in-JS overhead**: Pure CSS performance
3. **Easy customization**: Override variables in user CSS
4. **Framework agnostic**: Works with any styling solution

## 🧩 State Management

### Local State

Components manage their own state using React hooks:

```tsx
function DatePicker({ defaultValue, onChange }) {
  const [isOpen, setIsOpen] = useState(false)
  const [selectedDate, setSelectedDate] = useState(defaultValue)

  // Component logic
}
```

### Context State

Shared state uses React Context:

```tsx
// CalendarProvider provides shared calendar state
<CalendarProvider>
  <Calendar />
  <Calendar /> {/* Shares state with first calendar */}
</CalendarProvider>
```

### No External Dependencies

Zaman doesn't require Redux, Zustand, or other state management libraries. Everything is handled with React's built-in tools.

## 📦 Build Architecture

### Vite-based Build

```typescript
// vite.config.ts
export default defineConfig({
  build: {
    lib: {
      entry: './src/index.tsx',
      formats: ['es'],
      fileName: 'index'
    },
    rollupOptions: {
      external: ['react', 'react-dom'],
      output: {
        preserveModules: true, // Tree-shaking friendly
        preserveModulesRoot: 'src'
      }
    }
  }
})
```

### Output Structure

```
dist/
├── index.js              # Main entry
├── index.d.ts            # Type definitions
├── packages/             # Modular exports
│   ├── calendar/
│   ├── date-picker/
│   └── time-picker/
└── ... (all modules preserved)
```

### Tree-Shaking

Users can import only what they need:

```tsx
// Full import
import { DatePicker, Calendar, TimePicker } from 'zaman'

// Modular import (smaller bundle)
import DatePicker from 'zaman/DatePicker'
```

## 🚀 Performance Optimizations

### 1. **Memoization**

```tsx
// Components memoized to prevent unnecessary renders
export const CalendarItem = memo(CalendarItemComponent)

// Calculations memoized
const monthDays = useMemo(() => engine.getMonthDays(year, month), [year, month])
```

### 2. **Lazy Loading**

```tsx
// Month/Year pickers loaded on demand
const YearPicker = lazy(() => import('./year-picker'))
```

### 3. **Event Delegation**

```tsx
// Single click handler for all calendar items
<div onClick={handleCalendarClick}>
  {days.map((day) => (
    <CalendarItem key={day} />
  ))}
</div>
```

### 4. **CSS Variables**

No runtime CSS calculations - all styling uses pre-computed CSS variables.
